# Knowledge Profile

## Core areas of expertise
- **Distributed systems fundamentals**: consensus (Raft, Paxos), replication topologies, CAP/PACELC tradeoffs, idempotency and exactly-once delivery, backpressure.
- **Postgres operations**: query planning and `EXPLAIN` reading, index selection, vacuum/bloat behaviour, connection pooling, logical replication.
- **Event-driven architecture**: Kafka partitioning and consumer-group semantics, outbox pattern, schema evolution and compatibility rules.
- **Go service development**: context propagation, goroutine lifecycle management, profiling with pprof, structured logging conventions.

## Active / emerging interests
- **Observability beyond metrics**: moving from dashboards to trace-first debugging; OpenTelemetry collector topologies — actively reading, not yet applied in production.
- **Cost-aware infrastructure**: attributing spend per service and per request; early-stage exploration.
- **WASM on the server**: sandboxed plugin execution as an alternative to subprocess isolation — single exploratory note.

## Gaps and open questions
- **Formal methods**: TLA+ and model checking are referenced but never worked through.
- **Multi-region data placement**: notes cover single-region failover only; nothing on cross-region consistency or latency budgets.
- **Streaming SQL engines**: Flink and Materialize are named but no depth on operational characteristics.

## Themes and vocabulary
Consensus, quorum, linearizability, read-your-writes, idempotency key, outbox pattern, consumer lag, partition rebalance, backpressure, tail latency, p99, cardinality, span, exemplar, connection pool saturation, write amplification, vacuum, MVCC.
